# Видео для кейсов

Сюда кладутся видеозаписи работы ботов. Файл, положенный в эту папку под нужным именем,
автоматически появляется в кейсе на сайте — правки в коде не нужны.

## Какие имена ждёт сайт

| Файл | Кейс на сайте |
|---|---|
| `booking-bot.mp4` | AI-бот бронирования, база отдыха «Причал» |

Имя должно совпадать буква в букву, включая расширение `.mp4`.
Пока файла нет, в кейсе показывается кнопка со ссылкой на Google Drive — сайт не ломается.
Как только файл появится, кнопка исчезнет сама и на её месте встанет плеер.

Остальные видео пока живут на Google Drive. Положите их сюда с понятным именем
(например `vk-google-bot.mp4`) и скажите мне, к какому кейсу какое относится —
подключу так же, плеером вместо ссылки.

## Как загрузить через сайт GitHub

1. Открыть репозиторий → папку `assets/video`.
2. Кнопка **Add file** → **Upload files**.
3. Перетащить файл, внизу нажать **Commit changes**.
4. Через минуту обновить сайт с Ctrl+F5.

## Требования к файлу

- **Формат:** MP4, видео H.264, звук AAC. Другие форматы часть браузеров не проигрывает.
- **Размер:** до 50 МБ. Жёсткий предел GitHub — 100 МБ на файл, но чем меньше, тем быстрее
  открывается страница у клиента с мобильного интернета.
- **Длина:** 30–60 секунд. Нужен один законченный сценарий: вопрос гостя → ответ бота →
  оформленная бронь → оплата. Всё остальное лучше вырезать.
- **Вертикальное или горизонтальное** — не важно, плеер подстроится.

## Если файл весит больше 50 МБ

Сжать через ffmpeg:

```
ffmpeg -i исходник.mp4 -vcodec libx264 -crf 28 -preset slow -vf "scale=-2:720" -acodec aac -b:a 96k booking-bot.mp4
```

`-crf` управляет качеством: 23 — почти оригинал, 28 — заметно легче, 32 — уже видно потери.
`scale=-2:720` уменьшает высоту до 720 пикселей, ширина считается сама.

## Чего сюда не класть

Записи с личными данными клиентов: настоящие имена, номера телефонов, адреса, ссылки на оплату.
На видео с бронированием такое попадает в кадр легко — проверьте перед загрузкой.
